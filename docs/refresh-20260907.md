# Race-safe telemetry source shutdown and Collector compatibility

Reviewed and implemented 2026-09-07.

Source admission and the open/closing/closed transition now share a lock. Once closing begins, later publications return false with an explicit reason. Serialized, idempotent finish uses one absolute deadline for sentinel admission and exporter join; a timed-out close can be retried. Concurrent real HTTP producers and close reconcile all accepted event IDs. The clean-storage fault campaign now runs on checksum-pinned Collector 0.147.0 and 0.160.0, with exporter batching explicitly disabled.

## Why this scope

Backend/cloud infrastructure: backpressure, shutdown semantics, observability and evidence-driven dependency migration. [Dated official hiring and release review](market-review-20260907.md). Other portfolio projects already cover distributed queues and cloud provisioning; this change addresses defects at this repository’s own boundary. No additional framework is required.

## Tradeoffs and limits

Source acceptance, Collector HTTP ACK and sink fsync are different boundaries. A close deadline does not preempt an in-flight urllib request (2 s request timeout). Neither in-place persistent DB migration nor exactly-once delivery is tested. This is a custom OTLP logs writer, not a language SDK.

These are local CPU/Linux experiments with test-owned faults. No production traffic, cloud deployment, GPU execution, user count or service-level availability is inferred. Timing campaigns retain environment, raw samples and their original comparison method; this maintenance does not claim a performance improvement.
